Engineering guide · September 2026

One group. One object. One private database.

Splitnext is an HTTP API on Cloudflare Workers. Each group is routed to its own Durable Object, which owns the group’s members, credentials, invites, and private SQLite database.

HTTP edgeHono routes validate transport data and adapt it to domain operations.
Consistency boundaryA single GroupObject coordinates one group.
Persistent stateGroup data lives in per-object SQLite. D1 only supports global readiness metadata.
01 · Mental model

Start here

The four ideas that make the codebase click

You do not need prior Cloudflare knowledge. Think in terms of a stateless HTTP entry point delegating to many small, stateful group processes.

Module

A unit with a public interface and hidden implementation: a route group, state class, or the Worker.

Interface

Inputs, outputs, authorization, expected errors, and ordering constraints—not merely a TypeScript type.

Seam

A boundary where modules communicate. A good seam lets either side change without leaking internals.

Adapter

Translation at a seam. A route turns HTTP into a Durable Object call and maps the result back.

The invariant to remember

Addressing a Durable Object does not create a group. The group exists only after its schema and singleton state are created successfully.

What idFromName means

env.GROUPS.idFromName(groupId) deterministically maps a public group UUID to a Durable Object identity. The same group ID always addresses the same object.

What get means

env.GROUPS.get(id) returns an RPC stub. It does not copy data into the Worker and does not create the application-level group.

Why D1 still exists

The INDEX D1 binding currently holds only app_metadata for the readiness probe. Group records, members, access, and invites are not stored there.

02 · Runtime map

Responsibility flow

Thin adapters outside; state ownership inside

HTTP code understands requests and responses. The Durable Object coordinates transactions. Focused state modules own SQL and lifecycle rules.

04 · Storage

Per-group data model

The database belongs to the aggregate

Every diagram below describes the private SQLite database of one GroupObject. There is therefore no group_id column on member, access, or invite rows.

Singleton root

group_state.singleton = 1 permits exactly one group record in this database. The database itself supplies group scope.

Secrets at rest

Creation returns plaintext once. SQLite stores only SHA-256 hashes. Member access also requires the matching device_user_id.

Schema versioning

GroupDatabase runs Durable Object migrations and records the current version in object key/value storage under splitnext_group_schema_version. The repository’s migrations/ directory is only for D1.

05 · Request flows

Time runs downward

Two authorization paths, one transaction boundary

Normal operations prove permanent member access. Invite redemption proves temporary invite authority and then issues separate permanent access.

06 · System rules

Why the code looks this way

Async preparation, synchronous decisions

Web Crypto is asynchronous. Durable Object SQLite’s atomic API in this project is synchronous. Secret preparation and authoritative decisions therefore happen in two phases.

Phase 1 · outside transaction

Prepare cryptography

Generate random secrets and compute SHA-256 hashes asynchronously. This stage does not grant authority and does not mutate storage.

→

Phase 2 · transactionSync

Validate and write atomically

Re-check the credential or invite, load the live group, apply every related write, and commit or roll back together.

Optimistic concurrency

Group and member updates include expected_version. A stale caller receives version_conflict instead of overwriting newer state. No-op edits do not increment versions.

Tombstones

Deletion sets deleted_at. Member deletion also revokes access. Rows remain so future expense and history records can still refer to them.

Expected failures are data

Domain methods return unions such as { ok: false, error: 'version_conflict' }. Routes map those names to HTTP through responses.ts.

Unexpected failures are exceptions

Unexpected exceptions reach the global Hono error handler and become 500 { "error": "internal_error" }.

08 · Adding a slice

Extension path

Follow the existing seams

A future expense slice should travel vertically through the architecture while keeping each responsibility in its current layer.

Model the domainDefine expense schemas, result unions, and a module that owns expense invariants.
Migrate private SQLiteAdd the next Durable Object schema migration in groupDatabase.ts.
Coordinate in GroupObjectAdd small RPC methods guarded by actOnGroup; avoid duplicating lifecycle SQL.
Adapt through HTTPAdd a focused route file that validates input and maps domain outcomes.
Expose the typed clientExtend GroupClient so callers use Hono’s inferred contract.
Test observable behaviorDrive the Worker through the client; inspect SQLite only for hidden invariants.
Compose and verifyRegister routes in app.ts, update OpenAPI expectations, and run npm run check.
Placement test

Ask which module owns the invariant. Put the rule there, then expose the smallest interface its callers need.
