# Plan settle-up with the fewest payments

Settle up now shows one person the payments that involve them in a group-wide plan, so the plan has to be the same whichever person opens it and as short as possible; a greedy pairing could add needless payments that pass through people in the middle. Within each currency the client splits the nonzero balances into as many zero-sum sets as possible, since a set of k people settles in k − 1 payments, and settles each set greedily in a fixed order. The exact search is a bitmask over subsets, so it is limited to 14 people with a balance in a currency; larger groups fall back to the greedy plan alone, which needs at most one payment fewer than there are people. The plan is derived from balances on every device and is never stored, so recording any repayment, including a partial one, simply changes the next plan.
